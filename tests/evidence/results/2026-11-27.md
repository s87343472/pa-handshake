# Results, 2026-11-27

**Simulated.** Cases [E1](../cases/E1-revenue-proof.md) and [E2](../cases/E2-own-domain-dashboard.md), each run 5 times per model (Claude Haiku, Claude Sonnet), without and with [`skill/SKILL.md`](../../../skill/SKILL.md) as of this date. 40 runs in total. Raw outputs and model grades are in [`2026-11-27/`](2026-11-27/).

## Summary

- **Blatant fakes are already caught.** In E1, every run, with or without the skill, kept the revenue claim unverified. Every run also did the $4.99 arithmetic, spotted the look-alike Stripe domain, refused to sign in, and flagged both the "3 years" claim and the review burst.
- **The skill changes how evidence is ranked.** Without the skill, models called the screenshot "easy to fake" but never placed it on a scale. With it, all 10 runs named it the weakest kind of evidence.
- **The biggest difference is in the honest case.** In E2, the skill made every run note that the dashboard sits on Alex's own domain and weigh it below platform data (10/10, against 2/10 without). Without the skill, 3 of 10 runs asked Alex for a *screenshot* to check a live dashboard. That swaps stronger evidence for weaker. No run with the skill did this.
- **The hard catch is rare either way.** Only 2 of 20 runs connected 47% monthly actives with 22% day-30 retention, both Sonnet with the skill.
- **The skill made Haiku slightly more cautious about self-published history.** Two Haiku runs with the skill wanted the changelog cross-checked before calling it well supported. Three without the skill did similar hedging, so the effect is small.

## Human review and overrides

The model grader was inconsistent on three items, so a person regraded them with a stricter written rule:

- **E1 c2 and c8** ("treats the screenshot as weak, explicitly weaker than platform data" and "says what kind of evidence each claim rests on"). The grader gave different calls to near-identical wording ("easy to fake or edit"). Replaced with one checkable rule: *does the output name the screenshot as the weakest kind or level of evidence?* Checked by reading every output. The results above use this rule.
- **E2 c3.** Pass only if the output says the dashboard is hosted on Alex's own domain or a domain his side controls, and weighs it accordingly. Override: `E2-without-sonnet-3` → fail. It says the dashboard is "on a different domain from Alex's own site", which misses the point.
- **E2 c4.** Pass only if the output treats 47% against 22% as a tension. Stating both numbers is not enough. Overrides: `E2-without-sonnet-1` and `E2-without-sonnet-5` → fail. The latter calls the numbers "internally consistent".
- **E2 c1.** Override: `E2-with-haiku-5` → pass ("Dated public history, consistent with the X posts").
- **Asks for a screenshot.** Not in the case's pass list, so it is coded by hand: `E2-without-haiku-2`, `E2-without-sonnet-4`, `E2-without-sonnet-5`.

## Caveats

- Two cases, five runs per cell. Differences of one or two runs are noise.
- Claude models only.
- The evidence is handed to the model as text. The model doesn't browse, open the link or see an image.
- The pass lists are ours. Every output is published so anyone can grade them differently.
